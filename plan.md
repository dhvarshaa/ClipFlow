Stage 1 — make it deployable (covers your first hundreds): async job queue + object storage + signed download URLs + gunicorn + Docker with ffmpeg + a worker or two. This is the "proper web app" work I described last turn. Your merge is a one-shot render (no live timeline), so you can skip the whole real-time-preview engine for now — a big shortcut.
Stage 2 — scale to thousands: move the queue to Redis + a real worker pool (RQ/Celery) with autoscaling, push media to S3/R2 + CDN, add hardware-accelerated encoding, add cleanup/quotas/auth.
Stage 3 — only if you become a true editor: introduce the timeline-JSON model, browser preview (Canvas/WebGL + Web Audio), and proxy generation. This is a much bigger build and only worth it if you're moving beyond "merge/loop" into interactive editing.
